# プロジェクト全体統括 — Tatamu: AI 向け Rust 方言として生まれ、コメント外部化ツールとして完成するまで

> 2026-08-21 時点。対象期間は 2026-08-17〜08-21 の5日間(docs/00〜44)。
> 時系列の詳細は [docs/46-timeline.md](46-timeline.md)、転回篇の詳細は [docs/44-pivot-summary.md](44-pivot-summary.md)。

## 1. このプロジェクトは(現在形で)何か

**`tatamu` — Rust ソースからコメント・doc を完全可逆に外部化し、AI が必要な時だけ引き戻すためのツール。**

- `strip` がコメント・doc をサイドカー台帳(`.doc.md`)へ退避する。**コードは1文字も再整形しない**
- `restore` が完全復元する。全10検証コーパス・231ファイルで**バイト完全一致 100%**(CI ゲート常時実行)
- `owners`/`show`/`notes`(lens)で、stripped コードを文脈に置いたまま1項目の「なぜ」だけを従量取得する
- 効果: 文脈トークン **−50〜60%**(doc 文化のあるクレート)。フロンティアモデルでは
  コメント常駐(full)を精度で上回り、200k 文脈級モデルでは「そのクレートを1文脈で扱えるか」を分ける

名前の Tatamu(畳む)は当初「AI 向け Rust 方言」の言語名だったが、方言は自ら定義したゲートで
敗北して畳まれ、名前は「コメントを畳むツール」として存続している。この転回自体がプロジェクト
最大の成果物である — 以下、三幕で振り返る。

## 2. 第1幕: 方言の構築(08-17、docs/00〜25)

構想([docs/00](00-concept.md))は「人間の可読性を犠牲にしてでも LLM の開発効率とトークン効率を
最大化する、Rust に 1:1 変換される方言」。1日で:

- トークン実測 → 紙上文法 → LLM 生成実験 → トランスパイラ MVP(docs/01〜05)。
  **Stage 1 ゲート清算: 4モデル 24/24 コンパイル成功・規則違反ゼロ・トークン −27〜45%**
- Stage 2 機能群(docs/06〜19): LLM 向け構造化診断、cargo プロジェクト生成、doc のアウトオブバンド化、
  rustc エラー逆写像、C ABI/wasm/JS/TS/Dart FFI、Flutter 実機、v0.5〜0.6 仕様
- ドッグフーディング×2(docs/20〜21): 実ツールを Tatamu だけで開発し、**−13.8%(生成 Rust 比)/
  −42.2%(手書き Rust 比)** を実測 — 後にこの数字が tiktoken 測定の過大評価と判明する伏線

## 3. 第2幕: 相互変換と網羅の限界試験(08-18、docs/26〜33)

「既存 Rust 資産を Tatamu に取り込めるか」を syn ベースの逆変換器 rust2ttm(それ自体 Tatamu 製、
ドッグフーディング第3弾)で追い込んだ:

- 33ラウンド超の測定→分類→修正ループで、**18クレート・約7,900ファイル・約340万行の
  AST 同値 100%**(非対応は syn 非対応入力など2ファイルのみ。[docs/32](32-extreme-coverage.md))
- コメント台帳(インラインコメントの保全・復元、AST パスアンカー)がここで生まれる
  ([docs/29](29-comment-ledger.md))— **後の strip の直系の祖先**

この幕の技術資産(正規化 AST 比較、コメント座標系、テキスト処理の規律)が第3幕を可能にした。

## 4. 第3幕: ゲート実測、敗北、転回(08-18〜21、docs/34〜43)

自ら定義したゲート「AI にとって Rust と同等以上+明確なトークン削減」を2軸で実測し、
**2軸とも未達**(修正ループ: 完全同点/大規模文脈: 完全同点)。決定的だったのはアブレーション:

> once_cell 27,055 tok → コメントを外しただけの素 Rust 11,817(**−56%**)→ Tatamu 10,553(−61%)。
> **圧縮の主役はコメント外部化で、方言の固有価値は −11% だった**([docs/35](35-stage2-context.md))

ユーザー判断で方言を畳み、コメント外部化を素の Rust に提供する方向へ転回
([docs/36](36-strip-pivot.md))。以降4日間で:

- **可逆性の確立**: 実クレート適用で故障9クラスを検出・全修正し、全10コーパス
  **231/231 バイト完全一致・既知非一致ゼロ・CI ゲート化**(docs/38・43)
- **実利の実証**(実験4本+追試、[docs/44](44-pivot-summary.md) に総括):
  精度パリティ(docs/39)→ **lens > full・fits/doesn't-fit の分水嶺**(docs/40)→
  fetch-first 誘導で小モデルも回復(docs/40§6)→ 改修安全性は blind でも劣化なし(docs/41)→
  コメントのみの仕様は blind 崩壊・lens で 100% 回収(docs/42)
- **知識所在マップの確定**: コード痕跡のある知識は strip 無害、コメントだけが担う知識
  (設計判断の why・実装なき仕様)は lens が必要かつ十分 — **サイドカーは「失われる情報」でなく
  「従量制になった情報」**

## 6. プロジェクトレベルの学び

1. **ゲートを先に定義したから、畳めた。** 「未達なら畳む」を測定前に決めていたことで、
   サンクコスト(340万行 100% の逆変換器まで作った)に引きずられず転回できた
2. **敗北の測定が本命を発見した。** −56% vs −11% のアブレーションは、ゲート実験の副産物である。
   測るまで、誰も「主役はコメント外部化」と言語化していなかった
3. **機械ゲートが開発を駆動する。** AST 同値(第2幕)→ 不動点+バイト一致(第3幕)。
   検出された故障のほぼ全てはゲートが先に見つけた
4. **判定器も実験対象**。「full 込みで全滅したら判定器を疑え」は2回発動し、参照解の誤りも1回あった
5. **名前より仮説が資産。** Tatamu という名は生き残ったが、残ったのは名ではなく
   「AI の文脈コストは設計で下げられる」という検証済みの仮説と、その実装である
