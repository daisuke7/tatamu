# 初回ドッグフーディング レポート: ttmstat

> 2026-08-18 実施。ソース: `dogfood/ttmstat/src-ttm/`(main / scan / report の3モジュール、47行)

## 題材

**ttmstat** — Tatamu プロジェクトの統計 CLI。ディレクトリの `.ttm` を走査し、ファイル別の行数・fn/struct/enum 数・**o200k トークン数**を表または JSON で出力する。Tatamu 開発自身に使える実用ツールで、v0.5 までの機能を一通り実戦投入した:

- 複数ファイル構成(`--project`、クロスモジュール自動解決)
- 外部クレート: `#dep tiktoken-rs 0`(トークン計測)、serde + serde_json(`--json` 出力)
- データ付き enum: `enum Format {Table, Json {pretty bool}}`
- `#use std::fmt::Write`(`writeln!` を String に使うため — 設計どおり本当に必要になった)
- 修飾 derive: `+Debug,Clone,serde::Serialize`

## ワークフローの記録

書いたのは筆者(= LLM)。`--check` → `--project` → build → `--compile` → 修正 → 実行のループを回した:

1. **`--check`: 3ファイルとも診断ゼロ**(一発で構文準拠)
2. 初回ビルドで **E0308 が1件** → `--compile` が `report.ttm:5`(`Format::Table => {`)として rustc の help ごと返し、該当行を直接特定できた
3. 原因は**書いた Tatamu ではなくトランスパイラの穴**: fn 末尾式が複数行 `match` のとき、値アームの末尾に `;` が付く(14 で `unsafe` に入れた先読み判定が match に未適用だった)。`match` / `if` / `loop` に拡張して修正
4. 修正後、型検査通過 → **一発実行成功**。自分自身と実験コーパスを正しく測定(表・JSON とも)

**筆者が書いた Tatamu 自体の誤りはゼロ**(エラー1件はツール側)。修正込みで着手から完動まで実質1イテレーション。

## 実測

ttmstat 自身による自己測定と、.ttm ⇄ 生成 .rs の比較:

- ttmstat のソース: 3ファイル・47行・**672 トークン**(o200k)
- 生成 Rust: **812 トークン** → **−17.2%**

注: この比較は最も不利な条件(生成 Rust はコメントなし・最小形 = ほぼミニファイ Rust)であり、02 実験の「純粋な文法層の効果 15.9〜19.1%」と整合する。idiomatic な手書き/LLM 生成 Rust との比較では 35〜45%(05)、コメント込み実コードとの比較では 44〜46%(02)が適用される。

## 学び

### うまく機能したもの

- **`--compile` の .ttm 座標系エラー**が実際の開発ループで威力を発揮した。`.rs` を一度も開かずに開発が完結した(これは「AI にとっての開発効率」の核心 — 中間生成物を意識しなくてよい)
- `#use` / データ enum / 修飾 derive など v0.5 機能は全て設計意図どおりの場面で自然に必要になり、自然に書けた
- Rust の知識(`entry?.path()`, `.extension().map(...)`, イテレータ連鎖)がそのまま通用する — 「Rust の直感に沿わせる」方針の効果

### 摩擦(修正済み/残り)

| # | 摩擦 | 対処 |
|---|---|---|
| 1 | fn 末尾の複数行 match 値アームに `;`(トランスパイラバグ) | 修正済み(match / if / loop へ先読み拡張)。回帰なし |
| 2 | セミコロン挿入ヒューリスティックはこれで4回目の穴 — 行ベース設計の限界が見え始めた | Stage 3(自前 AST)への移行判断材料として記録。当面はコーパス+ドッグフーディングで穴を潰しながら進む |

## 判定

初回ドッグフーディングとして: **合格**。実用ツールが Tatamu だけで書け、エラーループは .ttm 座標系で完結し、トークンは最も不利な比較でも 17% 減。次回はより大きな題材(目安 200行超・複数データ構造・テスト付き)で、セミコロン・ヒューリスティックの残る穴と `--project` のスケールを試すのが良い。
