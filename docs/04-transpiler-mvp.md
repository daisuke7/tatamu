## アーキテクチャ

Stage 1 の設計方針(「ほぼプリプロセッサ」)どおり、**AST を作らない行ベース変換**。ただし全変換は文字列リテラル内を保護した上で適用する(string-aware)。

処理パイプライン:

1. **行ローカル変換** — `R<T>` 展開 → fn シグネチャ(`:` / `->` 復元)→ `:=` 束縛 → struct/const 展開
2. **セミコロン挿入** — ブロック文脈スタックで「値を返すブロック」を追跡し、末尾式にはセミコロンを付けない(下記)
3. **use 自動注入** — 出力を走査し、prelude マップ(HashMap / fs / env / PI / Box\<dyn Error\> など)に該当する `use` 行を先頭に生成
4. **インデント付与** — ブレース深度で rustfmt 風に整形(「畳む⇄広げる」の広げる方向)

### 一番の難所: セミコロン挿入

Rust は「文には `;`、ブロックの末尾式には付けない」を要求する。行ベースで正しく判定するため、ブロックを開く行を分類してスタックに積む:

- `fn … -> T {` → **fn-value**(末尾式あり)
- `fn … {` → fn-unit(末尾にも `;`)
- `let x = match … {` → **let-block**(閉じ `}` を `};` にする)
- `… => {` で親が値文脈 → **value-arm**(match アームの値ブロック)
- その他(for / if 文など)→ other(末尾にも `;`)

`}` の直前の行は、囲むブロックが fn-value / let-block / value-arm のときだけ末尾式として `;` を省く。

### 寛容モード(デフォルト)

弱いモデル(Haiku)の出力に頻出した「行末 `;` 残存」「ターボフィッシュ残存」は、入力段階で吸収する(`;` は剥がして規則的に再付与、ターボフィッシュは有効な Rust なのでそのまま通す)。03実験の「Haiku の違反は機械修正可能」をそのまま実装した形。

## 検証結果

コーパス = 手書き5本(paper-prototype)+ LLM 生成24本(4モデル × 6課題)= **29プログラム全てがクリーンに変換**(残存 Tatamu 構文なし・括弧平衡・シグネチャ/let 文の構造チェックをパス)。

テストが暴いて修正したトランスパイラのバグ3件:

1. `for` ブロック末尾の `map.insert(…)` に `;` が付かない(`insert` は `Option` を返すため型エラーになるところ)
2. 1行形式の `let x = match … {…}` に `;` が付かない
3. 値を返す match アーム内の末尾式に `;` が付く(`a / b;` → 型エラーになるところ)

## 既知の制限

- **S7(使用箇所からの型推論)は未実装** — `collect()` に注釈が必要なケース(`args := env::args().collect()` 等)は、出力 Rust がそのままではコンパイルできない。02レポートで検討した「軽量注釈」の仕様化が必要
- **コンパイル検証が未実施** — この環境に Rust ツールチェーンがない。`brew install rust` 後に全29本の rustc 検証が次の必須ステップ
- enum / ユーザー定義ジェネリクス / ライフタイム / モジュール / async は未対応
- **不正な Tatamu はそのまま通過する** — 03実験で Opus が生成した重複行(`mut stack = Vec::new()`)は不正な Rust として出力される。ここで「LLM 向けの構造化エラー」を返すのが Stage 2 の中核機能であり、最初の診断実装ポイントとして特定できた

### 仕様改定 v0.2: S7 の方針転換

「トランスパイラが使用箇所から型推論する」(S7)は放棄し、**「Rust が注釈を要求する箇所では Tatamu でも注釈を書く」**に改める:

- 束縛時型注釈: `x: Vec<_> := expr`(→ `let x: Vec<_> = expr;`)— 実装済み
- ターボフィッシュも必要なら許容: `.sum::<f64>()`(寛容モードで元々通る)

根拠:
1. 完全な使用箇所推論の実装は Stage 1 の範囲を大きく超える(実質型検査器)
2. モデルは対照群の Rust では正しく注釈できており、知識はそのまま転移する
3. **Haiku の全6本がコンパイル成功**した — ターボフィッシュを「違反」して残したことが結果的に注釈として機能した。規則で禁じるより Rust の要求に合わせる方が生成成功率に資する
4. 注釈のトークンコストは小さい(紙上5本の再計測: 27.6% → 25.9%、−1.7pt)

手書きサンプル5本は v0.2 注釈を追加し、**5/5 コンパイル成功**。
