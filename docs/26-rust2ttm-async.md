# Rust → Tatamu / async 対応 実現可能性検討レポート

> 2026-08-18 実施。想定ユースケース: **大規模 Rust プロジェクトのチームが、人間可読性を捨てて AI 開発効率を最大化する** — 既存資産の Tatamu 化(逆方向トランスパイル)と、未対応機能の解消が前提条件になる。
> 実験: `transpiler/rust2ttm.mjs`(プロトタイプ)、`/tmp` の tokio 検証プロジェクト

## 結論(先に)

| 課題 | 判定 | 根拠 |
|---|---|---|
| async | **対応済み**(本検討で実証) | tokio の実プログラムが transpile → 実行まで成功。必要だった修正は汎用の穴1件のみ |
| Rust → Tatamu | **実現可能**(プロトタイプで実証) | idiomatic Rust 393行を自動変換し、**テスト 17/17 通過・トークン −31.4%・doc をサイドカーに自動抽出**。ただし本番品質には syn ベース AST 化が必要 |

## 1. async — 「未対応」ではなく「未検証」だった

async fn / `.await` / `tokio::spawn(async move {…})` / `#[tokio::main]` / `tokio::select!` を含む実プログラム(並行 fetch + タイムアウト select)を書き、transpile → cargo run で**正しい実行結果**を確認した。

- async は「Rust のまま」領域に自然に収まり、**言語仕様の追加はゼロ**。`async fn f(a T) T` のシグネチャ変換も既存規則が処理
- 発見・修正した穴は1件: **引数位置の複数行ブロック**(`spawn(async move {…})` や値を返す複数行クロージャ)の末尾式に `;` が付く — async 固有ではない汎用バグで、「行内に未閉の `(` がありブロックを開く行は値文脈」の規則で解消
- `select!` のアーム、`.await` チェーンはそのまま通った

残る async 関連の未検証: async trait(RPITIT)、Stream、複雑な Pin 操作 — いずれも「Rust のまま」領域なので原理的な障害は見えていない。

## 2. Rust → Tatamu(rust2ttm)

### プロトタイプ実験

最も現実的な被験体 = **第2回ドッグフーディングで Sonnet が「最初から Rust で」書いた mdlite**(393行・doc コメント・`use` 文・`#[cfg(test)] mod tests`・rustfmt の複数行折り返し込み)。約150行の行ベースプロトタイプ `rust2ttm.mjs` で自動変換した結果:

```
元の idiomatic Rust : 3,593 トークン
変換後 Tatamu       : 2,464 トークン(−31.4%)
抽出サイドカー doc  :   600 トークン(オンデマンド読み込みに分離)
検証                : tatamuc で再展開 → cargo test 17/17 通過、CLI 実行正常
```

**「既存の Rust 資産を自動で 3 割引の Tatamu に畳み、ドキュメントはサイドカーに退避、動作は完全保存」が一発で成立した。**

### プロトタイプが実装した変換(すべて機械的)

`///`/`//!` → サイドカー(項目名アンカー)/ インライン `//`・`/* */` → 破棄(件数記録)/ rustfmt の複数行文 → 1行に結合(括弧深度+終端記号判定)/ `let` → `:=` / シグネチャ・derive・フィールド・const → Tatamu 形式 / `pub` 除去 / `use` → crate 内・prelude 該当は削除、それ以外は `#use` / `mod` 宣言削除 / `#[cfg(test)] mod tests` → トップレベル `#[test]` に平坦化 / 同 crate モジュール修飾(`html::escape`)→ 剥がして自動解決に委譲

### 副産物: 本体の重大バグ2件を発見・修正

逆方向の実データがこれまでにない入力パターンを持ち込み、tatamuc 本体の穴を暴いた:

1. **複数行 struct 定義が未対応**(enum は対応済みという仕様の非対称)→ 対応追加
2. **セミコロン挿入パスの文字列保護が機能していなかった**(`outsideStrings` の恒等適用は何も潰さない)。`"a [b"` のようなアンバランスな文字列リテラルがブロックスタックを汚染し `};` を誤出力 → 全該当パスを `stripLiterals`(中身潰し)に置換。これは既存コーパスが偶然踏んでいなかった**最古参級の潜在バグ**

ユニットコーパスに4ケース追加、74/74・全コンパイルコーパス回帰緑。

### 本番品質への道筋(行ベースの限界)

プロトタイプで成立したが、大規模 codebase には **syn ベース(Rust の公式パーサ)での再実装**が正道:

- 行ベースで拾えないもの: 式中コメントの正確な位置、マクロ内部、`use` の rename(`as`)/ネスト glob、cfg 分岐、複雑なフォーマット
- syn なら AST → Tatamu プリンタは素直(Tatamu は Rust AST の別表示に過ぎない)。**往復同値性の検証も機械化できる**: `rs → ttm → rs'` で `cargo test` 一致 + トークン列比較を CI ゲートに
- 見積り: syn ベース rust2ttm は Rust 製 CLI として 1〜2 週間規模(Tatamu 自身で書けばドッグフーディングにもなる)

### 移行ワークフロー案(大規模チーム向け)

1. モジュール単位で `rust2ttm` → 往復テスト同値ゲート → コミット(`.rs` は生成物として扱いに変更)
2. 非公開 API の情報喪失対策: 現状 Tatamu は全公開のみ → **`#priv` 指令の追加が移行の前提**(仕様追加は小)
3. doc はサイドカーに自動退避 → `--doc-check` を CI に
4. 以後の開発は LLM が `.ttm` 座標系で --check/--compile ループ

## 未解決課題(順不同)

- `#priv`(可視性の保存)— 移行用途では必須級
- マクロ定義(`macro_rules!`)の pass-through 検証、doc test(` ``` ` 内コード)の扱い
- 式中・文中コメントのサイドカー化規約(現状は破棄+件数レポート。「重要なコメントは失われる」ため移行時は diff レビュー必須)
- syn ベース化と往復同値 CI
