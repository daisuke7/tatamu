# 検討メモ: 「意図的な非対応」は Rust ⇄ Tatamu 相互トランスパイルの弊害になるか

> 2026-08-18。仕様 v0.6 §14.4 の3項目を、双方向変換(rs → ttm → rs' の往復を繰り返す運用)の観点で評価。

## 結論サマリ

| 項目 | rs → ttm で失う | ttm → rs で困る | 往復の安定性 | 判定 |
|---|---|---|---|---|
| インラインコメント禁止 | **失う(現状は破棄)** | なし | 初回移行時に喪失 | **唯一の実弊害。ただし対処可能** |
| FFI ジェネリック型 | なし | なし | 影響なし | 弊害なし(そもそも変換対象に現れない) |
| FFI enum タグ 32bit | なし | なし | 影響なし | 弊害なし(バインディング生成の範囲の話) |

## 1. インラインコメント — 唯一の実弊害、ただし範囲は限定的で対処策もある

### 何が起きるか

rust2ttm は `///` / `//!` を項目名アンカーでサイドカーに退避できるが、**式中・文中・行末のコメントは項目アンカーでは表現できず、現状は破棄**している(件数記録のみ)。大規模 Rust コードベースで特に痛いのは:

- **`// SAFETY:` コメント** — unsafe ブロックの契約説明。Rust 文化では実質必須で、消えると unsafe の監査可能性が下がる
- ロジックの意図・回避策の説明(「なぜ」系)、cfg 分岐や `#[allow]` の理由

### ただし、ユースケース前提で弊害の範囲は大きく縮む

想定ユースケース(人間可読性を捨てて AI 効率を最大化)では、移行後は **`.ttm` が正で Rust は生成物**になる。人間が Rust 側を編集しない以上、往復中に新しいインラインコメントは発生しない。したがって弊害は**「初回移行時に既存コメントをどう保全するか」の一点**に集約され、「往復のたびに壊れる」問題ではない。

### 恒久対処の設計案(必要になったら実装)

**コメント台帳方式** — doc 鮮度管理(docs/18)の機構をそのまま拡張する:

1. rust2ttm がインラインコメントを破棄せず、サイドカーに**位置フィンガープリント付き**で退避する(所属項目名+直後の文の正規化テキスト、行番号は使わない — コード編集で壊れないアンカー)
2. `--docs` 展開の逆として、Rust 生成時に元の位置へ再挿入するオプションを持つ(人間向け展開ビューの完全復元)
3. コードが変わってアンカーが浮いたら `--doc-check` が orphan として検出(既存機構)
4. **`// SAFETY:` は特別扱い**: 退避は必須、orphan は warning ではなく error(unsafe の契約が宙に浮くのは事故)

実装規模は doc 鮮度管理と同程度(アンカー設計が本体)。「コメント=言語外のメタデータで、項目 or 文にアンカーされる」という Tatamu の一貫した思想に収まる。

## 2. FFI ジェネリック型 — 弊害なし

これは **extern "C" 境界の話であって、トランスパイルとは独立**。ジェネリクス自体は「Rust のまま」領域として双方向に完全な往復ができる(hard-tasks / rust2ttm 実験で実証済み)。FFI に出せないのは Rust の extern "C" でも同一の制約(コンパイラが警告する)なので、**rust2ttm が受け取る現実の Rust コードに、そもそもこの形は存在しない**。

## 3. FFI enum タグ 32bit — 弊害なし(1点だけ注記)

これは言語の表現力ではなく**バインディング自動生成器の対応範囲**。`#[repr(C, u8)]` のデータ enum を Tatamu で書くこと自体は可能で(属性パススルー)、Rust への展開・コンパイルは正常に通る。欠けるのは `.h` / `.mjs` / `.dart` の自動生成だけ(警告してスキップ)。

- rust2ttm 方向: 既存 Rust に 8/16bit タグの enum があっても変換・コンパイルは無傷
- 将来その enum の FFI バインディングが必要になったら、タグ幅のパラメタライズは小さな実装で足せる(repr から tag size/align を取るだけ)

## 推奨

- 相互トランスパイル(syn ベース rust2ttm)に着手する際、**コメント台帳を初期スコープに含める**(後付けだと初回移行で失ったコメントは戻らないため)
- 2・3 は現状のままで問題なし
