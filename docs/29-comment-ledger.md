# v0.6.1: コメント台帳(インラインコメントの保全・復元)実装レポート

> 2026-08-18 実施。[28](28-intentional-gaps-vs-roundtrip.md) で特定した「相互トランスパイル唯一の実弊害」への対処。

## 実装

### 台帳形式(サイドカー `.doc.md` の項目節内)

```
~ tail `i += 1`#6: consume the closing fence
~ above `if chars[i] == '*' && !starts_with(&chars, i, "**") {`: Only treat a lone `*` as ...
```

- **アンカー = .ttm の行テキスト**(行番号ではない — コード移動に耐える)。同文が複数ある場合のみ `#n`(ファイル内出現序数)を付与
- `above`(行の上のコメント)/ `tail`(行末コメント)の2種
- 所属項目の節に置かれるため、doc 鮮度管理と同じ生活圏で管理される

### パイプライン対応

| 段 | 動作 |
|---|---|
| **rust2ttm** | 破棄していた `//`・`/* */` を抽出し台帳化(複数行ブロックコメントは above 連行、行末は tail)。変換後の .ttm 行をアンカーに採用 |
| **tatamuc --docs** | 行番号マップでアンカー → 生成 Rust の該当行を解決し、`// …` を**元の位置に再挿入**(above は同インデントで直上、tail は行末) |
| **--doc-check** | アンカーが .ttm に存在しない(序数不足含む)→ `comment-orphan`。**`SAFETY:` で始まるコメントは error**(unsafe 契約の宙吊りは事故)、他は warning |
| **--doc-sync** | 台帳エントリを保存したまま再出力(序数込み) |

## 検証

- **E2E(mdlite-rust 往復)**: idiomatic Rust の6コメント全てが台帳化 → `--docs` 展開で**元の Rust と同一位置に復元**(`i += 1; // consume the closing fence` が closing-fence 消費の if 内に、3行の説明コメントが正しい順序で `*` 判定の直上に)。cargo test 17/17 維持
- **序数アンカーの実地確認**: `i += 1` は同ファイルに10回出現 — 序数なしなら誤位置に付くところを `#6` で正しく解決(この重複は実データが即座に教えてくれた)
- **orphan 検出**: アンカー行を書き換えると comment-orphan(warning)、SAFETY 文言なら error
- ユニットコーパス 87/87(台帳4ケース追加)、サニティ 29/29

## 位置づけ

- これで docs/28 の結論は「**相互トランスパイルの弊害はゼロ**(残る非対応はすべて C ABI の性質か、台帳で保全される設計)」に更新される
- 既知の限界(設計時から想定): 序数アンカーは上流に同文行が挿入されるとズレ得る(docCheck では検出不能)。syn ベース化の際に AST パスアンカーへ進化させる
