# サブディレクトリ再帰と実クレート硬化: 226ファイル・9コーパスで fixpoint 全通過 / バイト完全一致 225

> 2026-08-20 実施。docs/37 の続き。バックログ筆頭「strip のサブディレクトリ再帰」を実装し、
> そのまま実クレート4種(フルソース)に適用して見つかった問題を全て潰した。

## 1. サブディレクトリ再帰

- `rs_names` を再帰走査に変更(相対 stem `de/mod` 形式を返す)。strip/restore/roundtrip/lens が
  そのまま `src/` 全体を扱えるようになった
- symlink はスキップ(serde の `src/core -> ../../serde_core/src` が実例。辿ると重複・ループ)
- 出力側は親ディレクトリを自動作成

## 2. 実クレートで踏んだバグと修正(すべて roundtrip ゲートが検出)

適用先: serde_core / serde / serde_derive / regex(top) / regex-syntax / regex-automata / memchr /
once_cell / 自分自身 = **計226ファイル**。初回適用時の主な故障と対処:

1. **doc 行内 URL の `/*` 誤認**: `docs.rs/linked-hash-map/*/...` をブロックコメント開始と誤認して
   後続を飲み込む → 行コメント開始より後の `/*` は無視
2. **cfg 双子の owner 衝突**: `#[cfg(std)]` / `#[cfg(not(std))]` で同名 fn が2回宣言されると
   2つ目の docs が消失 → サイドカー節に序数シャドウ `## Owner::name#2` を導入(anchor の `#n` と同じ規約)
3. **多行属性の walk-up 漏れ**: `#[cfg_attr(...)]` が複数行だと docs が属性の下に復元される
   → 結合行(joined)単位で属性をスキップ
4. **rustfmt 折返し where 句でスコープ不成立**: `impl T where A: B, C: D,` + 次行 `{` で
   impl スコープが積まれず内部が全て未解決 → pending scope(継続行許容)で `{` 行に接続
5. **enum struct 風 variant のフィールド doc 消失** → variant がフィールドスコープを作るように
6. **fn ローカル item の doc 消失**(fn 内 struct 等)→ sticky owner 配下のラベルで解決
7. **`macro_rules!` が owner にならない** → 認識追加(マクロ直上の巨大 doc が保持される)
8. **台帳アンカー終端の誤パース**: コメント本文に `` `: ``(インラインコード)があると右端探索が壊れる
   → 左から最初の `` ` `` + `:`/`#n:` で終端
9. **行頭 `*self;`(デリファレンス)をブロックコメント継続と誤認** → コメント行マップのプリパスで
   walk-up を厳密化(kept ブロックを1単位として跨ぐ/ブランクは上にコメントがある時だけ横断)

## 3. バイト完全一致のための形式保存(台帳フォーマット拡張)

- **`/*! ... */` ブロック形式の保持**: クリーンな standalone ブロックはサイドカーに `~ form: block`
  を記録し、`//!` 正規化せず元の形で復元(regex 系はほぼ全ファイルこの形式)
- **非 doc ブロックコメントは externalize しない**: `/* commented-out code */` や行中の
  `{ /* below */ }` は verbatim 維持(SAFETY 特例を一般化)。希少でトークン利得も小さく、
  可逆性の方が価値が高い
- **コメント独自インデント**: アンカーと違う桁のコメントは `above+4` / `above-2` デルタで復元
- **テールコメントの桁揃え**: `55,  // '\x00'` の複数スペースを `tail+1` デルタで復元
- **前書きコメントの順序**: doc ブロックやモジュール intro より前に置かれたコメントは `^` マーカー
  (`above^`)でランク付けし、復元時に doc の上に置く
- **EOF コメント**: ファイル末尾でアンカーを持たないコメントは stripped 側に残す(消失防止)
- 内部整理: pending コメントを `AboveNote` struct 化(detached / indent / pre_docs / pre_intro /
  sealed)。sealed は「kept ブロック以降のブランクは自分の detach 情報ではない」ことを表す

## 5. 既知の制限(更新)

- モジュールヘッダで「前書きコメント + 空行 + intro」の空行配置は完全復元できない場合がある
  (pool.rs 型。データは保全、順序のみ移動)
- `/** */`(アイテム doc のブロック形式)は `///` に正規化されたまま(未対応。今回のコーパスでは非出現)
- doc と item の間に挟まれたコメントと doc の相対順序は「doc の前/後」の2値まで
- インラインで保持されるブロックコメント内に `//` や波括弧が含まれる病的ケースは未対応
