# 模倣不能な新規設計実験: コード痕跡ゼロの仕様は blind で崩壊し、lens は full と完全同点で回収する

> 2026-08-21 実施。docs/41 の残課題「隣に模倣対象が無い新規設計」。総コスト ≈ $3.5。
> ハーネス: `experiments/novel-design/`(合成クレート corvid/ 込み)。

## 1. 設計 — 模倣を構造的に排除する

docs/41 で「契約は隣接コードの実装パターンが運ぶ」と分かった。ならば**実装がまだ存在しない関数**を
書かせれば、模倣経路は構造的に消える。実クレートでは作れない状況なので、合成クレート **corvid**
(架空のワイヤプロトコル、5ファイル)を作成した:

- 仕様は **doc コメントのみ**に存在し、当該関数は `todo!()`(= strip すると仕様が文脈から消滅)
- 仕様の決定点は**わざと反慣習**: 長さフィールドは**リトルエンディアン**で **payload のみ**を数える、
  チェックサムは rot3-XOR(init 0x5A)で **payload のみ**、varint は **MSB グループ先行**(反 LEB128)、
  seq は **7 始まり +2 刻み**、3個目のデータごとに自動 heartbeat — 「常識で推測」では部分点止まり
- 課題3本: `encode_frame` / `encode_uvar` / `Session::new`+`push`
- 判定: ハーネス内 JS 参照実装から生成したテストベクタで **per-vector 採点**(計27点)。
  todo!()/panic は catch_unwind で 0 点化。sanity 9ケース検証済み
  (Rust 参照解 27/27、慣習推測解 — LEB128・BE長・全域チェックサム・seq 0始まり — は約30%、todo 放置 0)

## 2. 結果(27点満点)

| | blind | lens(fetch-first)| full |
|---|---|---|---|
| Haiku | 6/27(22%) | **27/27** | 27/27 |
| Sonnet | 3/27(11%) | **27/27** | 27/27 |

- **lens は full と完全同点**。fetch は的確(`notes frame` → `notes encode_frame`、
  `notes session` → `notes Session::push` …)、Haiku ですら課題あたり 2〜3 回の参照で満点
- **blind は慣習推測水準以下に崩壊**。varint は両モデルとも標準 LEB128 を書き(1バイト値のみ正解)、
  セッション規則(7始まり+2刻み+自動 heartbeat)は 0/10 全滅
- 危険モードの実例: sonnet/blind は「長さフィールドに varint を使い、チェックサムは省略」という
  もっともらしい独自プロトコルを堂々と実装(しかも未実装の `encode_uvar` に依存して実行時 panic)。
  **どちらのモデルも「仕様が分からない」とは言わず、確信を持って非互換コードを出荷した**

## 3. 三部作の完成 — 知識の所在マップ(docs/40〜42)

| 知識の種類 | 所在 | strip の影響 | 実験 |
|---|---|---|---|
| コードに痕跡のある事実(定数・構造・アルゴリズム) | コード | 影響なし(blind でも取れる) | docs/40 d1/d2/d5 |
| 実装パターンに刻まれた契約(ordering・状態機械・解放) | 隣接コード | 影響なし(模倣で正しく書ける) | docs/41 全18ラン |
| 設計判断の why(やらない理由・API を作らない理由) | **コメントのみ** | blind で失われ、lens で回収 | docs/40 d3/d4/d8 |
| 実装が存在しない仕様(プロトコル・規約) | **コメントのみ** | **blind で崩壊(11-22%)、lens で完全回収(100%)** | 本実験 |

結論: (a) パス(strip+サイドカー+lens)は、コード痕跡のある知識には無害で、
コメントしか担い手の無い知識には **lens が必要かつ十分**。fetch-first 文言との組み合わせで
小モデル含め full と同等 — サイドカーは「失われる情報」ではなく「従量制になった情報」であることが
全知識クラスで実証された。

## 4. 限界

- corvid は合成コーパス(私が仕様と課題の両方を設計)。反慣習の度合いは私の裁量であり、
  blind のスコアは仕様の「推測可能性」設計に依存する(慣習推測解 ≈30% とほぼ一致しており妥当)
- ベクタ採点は表面バイト一致 — 意味的に等価な別解は原理上ありうる(今回の仕様では一意)
- fetch-first 文言のみ検証(docs/40 §6 の plain 文言なら lens でも取りこぼす可能性はある)
