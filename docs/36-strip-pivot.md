# 方針転回 (a): 素の Rust 向けコメント外部化 — `strip` / `restore` / `roundtrip`

> 2026-08-19 実施。docs/35(Stage 2 ゲート大規模文脈軸・未達)の帰結としてユーザーが選択した方針:
> **「方言を畳み、圧縮の主役だったコメント・doc の帯域外化を素の Rust に対して提供する」**。
> 実装: `dogfood/rust2ttm/src-ttm/strip.ttm`(新モジュール、約470行 Tatamu)+ main ディスパッチ。

## 何を作ったか

rust2ttm バイナリに3サブコマンドを追加:

- **`strip <src-dir> <out-dir>`** — .rs からコメント(`//`、`/* */`)と doc(`///`、`//!`、`/** */`、`/*! */`)を
  サイドカー台帳(`<mod>.doc.md`)へ退避し、**コードは1文字も再整形しない**純テキストの stripped .rs を出力。
  - `// SAFETY…` 行は継続行ごとインライン温存(unsafe 直上の不変条件を編集時に見えなくしない)
  - マクロ呼び出し本体の内側は**完全 verbatim**(コメントも含め一切触らない — tatamuc と同じ哲学)
  - 各ファイルで **AST 自己検査**: doc 属性を除去したトークン列が原文と一致することを検証(`AST-VERIFIED`)
- **`restore <stripped-dir> <out-dir>`** — サイドカーからコメント・doc を元位置に再挿入
- **`roundtrip <src-dir> <work-dir>`** — strip → restore → strip の**不動点検証**+原文とのバイト一致率報告

## 台帳フォーマット(strip モード)

- doc はセクション本文、コメントは `~ above|tail|float \`物理行アンカー\`#n: text`
- **アンカーは物理行**(v0.6.1 の論理行から粒度向上): クロージャ内・複数行文の内側でも正確な位置に復元
- **owner はスコープスタックで解決**: インライン `mod`(ネスト可)、`impl`/`trait`(`Type::method`)、
  `enum`(`Enum::Variant`)、`struct`/`union`(`Struct::field`)、`use`(re-export doc)、
  ファイル先頭は `(mod)` 擬似 owner。序数は owner スコープ内で数える
- `float` = コメント塊と anchor の間に空行があった印(復元時に空行1つを跨いで挿入)
- コメント本文は内部インデント保持(`//   • item` の整列が崩れない)。`////…` 区切り線も正確に往復
- 本文行の `#`/`~`/空行はエスケープ(`\` 前置)して doc 内 Markdown 見出しと台帳構文の衝突を防止

## 検証結果(5コーパス・25ファイル)

| コーパス | ファイル | AST 検査 | 不動点 | バイト完全一致復元 |
|---|---|---|---|---|
| once_cell(実クレート) | 5 | 5/5 | 5/5 | **5/5** |
| serde 最上位 | 2 | 2/2 | 2/2 | **2/2** |
| memchr | 6 | 6/6 | 6/6 | 5/6 |
| regex 最上位 | 6 | 6/6 | 6/6 | 4/6 |
| rust2ttm 自身(生成 rs) | 6 | 6/6 | 6/6 | **6/6** |
| **計** | **25** | **25/25** | **25/25** | **22/25** |

非一致3件は全て `/*! … */` ブロック doc を `//!` 行形式へ意図的に変換するもの(情報は完全、AST 同値)。
**strip→restore が元ファイルと1バイトも違わない**という保証は、convert 経路の AST 同値ゲートより強い。

開発中に不動点ゲートが実バグを2件検出(単独行コメントの握りつぶし / `use std::{` の owner 空文字化による復元不能)—
「強い往復ゲートを先に立てる」方法論がそのまま機能した。

## 圧縮の実測

文字ベース(stripped vs 原文):

| コーパス | 圧縮 | 備考 |
|---|---|---|
| once_cell | −56% | doc 豊富 |
| serde 最上位 | −56% | |
| memchr | −46% | |
| regex 最上位 | −89% | lib.rs がほぼ doc |

**Claude トークン実測(once_cell)**: 原文 27,055 → stripped **12,654(−53.2%)**。サイドカーは 15,352 で、
常時同梱すると ±0 — つまりこの圧縮は「削減」ではなく**従量制への転換**(コメントは必要な時だけ文脈に載せる)。
docs/35 の結論どおり、この −53% は方言なしで得られ、方言の追加寄与(−11%)とは独立。

## 既知の限界(v1)

- `/*!`/`/**` ブロック doc は `//!`/`///` 行形式へ正規化(バイト非一致の唯一の源)
- マクロ**呼び出し**本体内のコメントは外部化しない(意図的 verbatim)。`macro_rules!` 定義も同様
- フラットディレクトリのみ(サブディレクトリ再帰は未対応)
- 空行2つ以上で detach されたコメントは空行1つ分として復元
- SAFETY ブロックコメントは行頭開始のもののみ温存
- 文内 doc コメント(文の上の `///`)は owner 不在時に警告付きで破棄

## convert(方言)経路の現状メモ

verify-roundtrip.sh を rust2ttm 自身の生成 rs に掛けると、既存コード3項目(`flatten_spacing` /
`convert_one` / `apply_priv`)+今回の新規コード数項目が AST 不一致になる(HEAD 時点のコードでも再現 =
今回の退行ではなく、自己変換は元々未検証だった)。方針 (a) では convert 経路は非中核のため追わず、記録のみ。
transpiler ユニットテストは 163/163 維持。
