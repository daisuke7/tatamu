# 大規模実 crate でのスループット・網羅率測定レポート

> 2026-08-18 実施。ハーネス: `experiments/rust2ttm-coverage/measure.mjs`(ファイル単位で 変換 → 再展開 → AST 同値検証)

## 測定対象と最終結果

実在の著名 OSS 3クレート(テスト/example 除くソース本体):

| crate | files | 行数 | AST同値 | mismatch | 再パース失敗 | 同値率 |
|---|---:|---:|---:|---:|---:|---:|
| ripgrep | 86 | 49.5k | 65 | 7 | 14 | **75.6%** |
| serde | 54 | 26.4k | 35 | 5 | 14 | 64.8% |
| clap | 119 | 42.2k | 70 | 26 | 23 | 58.8% |
| **合計** | **259** | **118.1k** | **170** | 38 | 51 | **65.6%** |

- **スループット: 82k 行/秒**(118k 行の変換が 1.4 秒)— 100万行のコードベースでも変換自体は十数秒のオーダー。**性能は問題にならない**
- 判定は最も厳しい基準(正規化 AST の完全同値)。「変換失敗」「パニック」は **0件** — 全ファイルが何らかの Tatamu を出力し、失敗はすべて再展開後の差分として検出された

## 測定サイクルが品質を駆動した(15% → 76%)

初回測定は ripgrep で **15.1%**。「測定 → 失敗を頻度分類 → 支配的クラスを修正 → 再測定」を5ラウンド回して **75.6%** まで引き上げた。修正一覧:

| ラウンド | 発見(頻度順) | 修正先 |
|---|---|---|
| 1 | impl 内メソッドの `///` doc が本文と結合し構文破壊 | rust2ttm(doc 深層strip+サイドカー収集)、tatamuc(--doc-check が impl 内 fn を受理) |
| 2 | 複数行文字列リテラル(`\` 継続・生改行)の破壊 | rust2ttm(Rust 意味論どおりの1行畳み込み) |
| 2 | fn 本体内の `use …::{…}` に `;` が付かない | **tatamuc**(use 文規則) |
| 3 | ネストジェネリクス(`<P: AsRef<Path>>`)でシグネチャ変換破綻 | rust2ttm(convert_sig を深度スキャンに全面書き換え) |
| 3 | ユニット/タプル struct の derive 後置が未定義 | **tatamuc**(`struct Marker +Debug` / `struct Wrap(u8) +D` 対応 = 仕様拡張) |
| 4 | 1行畳みされた「match 入りクロージャ文」が match アーム扱いされ `;` 消失 | **tatamuc**(アーム判定を「`=>` が最初の `{` より前」に厳格化) |
| 4-5 | compare の意味等価パターン群: アームのブロック化差 / `()` vs `{}` / 全 Punctuated の末尾カンマ / macro_rules 最終 `;` / ブロック末尾マクロ文の `;` / 文字列・バイト列リテラルの表記差 / アーム区切りカンマ | compare(正規化を7種追加) |
| 5 | 複数属性持ち struct への +derive 挿入位置 / `b"…"` バイト文字列 / 型引数の末尾カンマ | rust2ttm |

tatamuc 本体の実バグ・仕様穴も **3件**発見(ユニットコーパスへ追加、96/96)。既存の全コーパス・mdlite ラウンドトリップ(ROUND-TRIP OK)に回帰なし。

## 残る失敗クラス(分類済み・次サイクルの入力)

1. **属性の順序差**(clap に多い): `#[derive]` を +List 化→再付与する際に他属性との順序が入れ替わる。意味等価 — compare の属性ソート正規化で解消可能
2. **struct フィールド上の cfg 属性**: `#[cfg(feature = "env")]` 付きフィールドが複数行 struct 変換で壊れる — tatamuc のフィールド行属性対応(仕様拡張)が必要
3. **serde 級の高密度ネスト**(visitor パターンの深い入れ子)での畳み込み残欠陥

いずれも原因特定済みで、支配クラスから潰せば 80〜90% 台は現実的な射程。真の限界(macro 定義内の複雑トークン等)はまだ現れていない。

## 追記(同日): 失敗クラス1・2の解消

| クラス | 対処 | 結果 |
|---|---|---|
| 1. 属性の順序差 | compare の正規化に**属性リストのソート**を追加(項目・impl/trait メソッド・フィールド・variant の全箇所) | clap の mismatch 群が解消 |
| 2. フィールド上の cfg 属性 | **tatamuc の実バグ**: 複数行 struct/enum 本体の `#[…]` 行がフィールド扱いされ `,` を付けられていた → 属性行のパススルーを追加(ユニットケース2件追加、98/98) | clap/ripgrep の parse-fail 群が解消 |

再測定: **65.6% → 73.0%**(ripgrep 81.4% / clap 70.6% / serde 64.8%)。クラス1・2の残滓はゼロを確認。ラウンドトリップ・全コーパス回帰なし。

残る失敗(=旧クラス3)の精緻化: (a) ガード付きアーム・クロージャ本体のブロック化差と where 節末尾カンマ(compare 正規化の追加で対処可能な意味等価群)、(b) **複数行 struct リテラルの join 分割**(join が `{` ブロックとリテラル `{` を区別しない設計問題 — 本丸)、(c) `impl Trait` 入れ子引数のシグネチャ変換、(d) マクロ内複数行文字列の残ケース。

## 追記(2026-08-18): 旧クラス3 (a)〜(d) の解消

| 項目 | 対処 | 同値率 |
|---|---|---|
| (a) アーム/クロージャのブロック化差・where 末尾カンマ | compare 正規化3種(単文ブロック unwrap をアーム/クロージャで共用、マクロ文含む) | 73.0% → 75.3% |
| (b) 複数行 struct リテラルの join 分割(本丸) | join に**リテラル畳み込み**を追加 — `{` 終端行の次行がフィールド形(`name:` / `..` / shorthand)ならブレース収支が戻るまで1文に畳む。match アーム(`pat =>`)や文はこの形にならないため誤爆しない | → 76.8% |
| (c) impl Trait 入れ子引数 | **tatamuc の実バグ**: パラメータ分割が負の先読み正規表現でネスト `<(` 内のカンマを割り `impl:` を捏造 → 深度追跡スキャンに置換(fn ポインタの `->` の `>` はスキップ、裸 impl Trait はパススルー)。rust2ttm 側にも同ガード | 199件(内訳シフト) |
| (d) マクロ内トークン列の破壊 | **両方向とも quote!{} 等の本体にTatamu 変換を適用していた**(rust2ttm は `->` を剥がし、tatamuc は `;` 挿入・シグネチャ再展開)→ 両側に「マクロ呼び出しの自デリミタが行末で開いたままなら verbatim モード」を追加(深度追跡、macro_rules 除外、閉じ行は semi 論理に復帰)。さらに1行畳みマクロで tatamuc の transformFnSigs が**非シグネチャ `fn` の前置テキストを喪失**・**Rust 形式に `->` 二重付与**する実バグ2件を修正(冪等化) | → **79.9%** |

再測定: **73.0% → 79.9%**(ripgrep 81.4% / serde 79.6% / clap 79.0%)。ユニット 104/104、mdlite ラウンドトリップ OK 維持。特に (d) は「マクロ内が黙って壊れる」系で、compare ゲートが無ければ静かな腐敗になっていた種類の欠陥。

残る失敗 52件の分布: 依然すべて検出可能な差分(パニック/変換不能ゼロ)。mismatch 23件(`<unnamed>` = impl ブロック内の差が主)、parse-fail 29件(`;` 系が主 — 深いネスト/複雑な折返しでのセミコロン規則の残穴)。

## 追記(同日): 「改善不能まで」の継続ラウンド — 全7クレート 100%

(a)〜(d) 解消後の 79.9% から、測定→分類→修正ループをさらに 15+ ラウンド継続した。

**最終結果: 7クレート 905ファイル・444k行、全て AST 同値(mismatch 0 / parse-fail 0 / panic 0)。**

| セット | crate | files | 同値 |
|---|---|---:|---|
| チューニング | ripgrep / serde / clap | 259 | **100%** |
| ホールドアウト1(未調整で初測 98.3%) | tokio / regex | 523 | **100%** |
| ホールドアウト2(未調整で初測 91.9%) | syn / bat | 123 | **100%** |

主な発見と修正(抜粋、各ラウンド1コミット):

- **意味破壊級(compare が無ければ静かな腐敗)**: raw string の `\n` 畳み込みで内容が変わる(→ convert 時に通常エスケープへ正規化)、`bar`/`"-r"`/`"\\r"` の `r` を raw string 開始と誤認して実デリミタを飲み込む(→ リテラル走査を最左優先の交互1本に)、テキスト層カンマ除去が macro_rules パターン `(…, >=)` の区切りを食う(→ `>` を対象から除外)、`Token![=]` 型の中の `=` で let 変換が分解(→ 両側ブラケット対応)
- **セミコロン文脈の一般化**: 代入 `x.y = if … {`・複合代入・1行代入 if・`#[attr] stmt` 1行形・(pub) use 全形・fn 末尾直前の let 文・`}` 終端 return、アーム判定のトップレベル `=>` 化、`..=` は代入でない
- **シグネチャ**: where 節(`-> where` 捏造の解消+複数行 where の遡り文脈)、パラメータ属性(文字列込み)、struct 分解パターン引数、複数行 where 付き struct(フィールド誤変換・derive 位置)
- **compare 正規化の追加**: 全 Punctuated 末尾カンマ(型引数/ジェネリクス/シグネチャ/タプル/配列/struct式)、文位置ブロック式の `;`、`;` 付き単文マクロアームの unwrap、macro_rules アーム本体デリミタの Brace 統一、マクロトークン内 doc(inner 含む)、Punct spacing
- **変換基盤**: 変換をリテラルマスク(プレースホルダ)上で実行、transformFnSigs の冪等化と非シグネチャ経路のテキスト喪失修正、struct リテラル畳み込みは文字列が開いている間は停止・属性フィールドは先読みで判定

ユニットコーパスは 104 → **129 ケース**(全修正に最小再現を追加)。mdlite ラウンドトリップは全ラウンドで OK 維持。

ホールドアウトの初測値(tokio+regex 98.3%、syn+bat 91.9%)は、チューニングセットへの過適合ではなく一般規則の獲得が起きていることを示す。残る既知の失敗は**ゼロ** — 「改善不能」ではなく「現時点の測定対象では改善対象が尽きた」状態。次の限界は新しいコードパターンを持つ crate が教えてくれる(測定ハーネス: `measure.mjs`、単ファイル診断: `diag.mjs`)。

## 結論

- **スループットは実用域**(82k 行/秒)
- **網羅率 65.6%(最良 75.6%)は「5ラウンドの改良でここまで来た」中間値**であり、失敗は全て分類・再現可能な形で残っている。同値ゲート駆動の改良ループが機能することが実証された — これがこの測定の最大の成果
- 「変換できず情報が消える」モードは存在しない(失敗=検出可能な差分)ため、実プロジェクト移行では「同値ファイルから段階的に移行し、残りは追って対応」という運用が今日から可能
